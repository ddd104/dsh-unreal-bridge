# 外观、参考图与行为验证

按当前目标选择关键特征与验证方法，不将历史案例的形状、颜色或控制方式当作默认要求。匹配图像时使用源图分析；没有参考图时，以用户描述、项目约定和已确认的目标为依据。动态行为使用参数与时序检查；仅修改已有参数值时保持局部验证范围。

## 在不改变原图含义的前提下测量

先确定参考的用途：直接呈现的图案、具有已知通道含义的贴图，还是包含几何、光照和后处理的照片/渲染结果。对图案可以分析颜色与覆盖；对数据贴图应核对通道用途；对受光表面应提取外观特征，不能把截图像素直接当作 Base Color 或声称已反推出唯一的粗糙度、金属度、法线等参数。

检查原始图像及其可用的解码元数据：像素尺寸、是否存在透明度（alpha）通道、图像方向，以及色彩空间和色彩配置文件的处理方式。记录选取的区域或采样坐标，并区分实测值与估算值。

如果可以使用 `unreal_image_analyze`，先检查其实际接口定义，再使用它支持的原始像素、区域、alpha 以及可选的背景合成结果。不要假设它能识别形状的语义或反推出着色器参数。如果它不支持某项所需测量，应报告这一限制，不得编造测量精度。

将以下数据区分开来：

- 解码后的原图 RGB 和 alpha，包括工具是否转换了色彩空间或位深。
- 将这些像素合成到指定背景上的结果，以及工具报告的合成约定。
- 材质输入值和引擎最终渲染出的外观。

当 alpha 表示图像覆盖率时，对于 8 位通道将其值除以 255 归一化；单个采样值不能证明整片区域的不透明度恒定。检查有代表性的内部区域和边缘表现。完全透明像素的 RGB 不能作为可见颜色的证据。已经与背景合并的截图无法唯一确定原始 alpha 或材质颜色；数据贴图中的 alpha 应按已知用途解释。

将采样用于具体决定，记录“观察到的特征 → 对输入/合成的解释 → 实现与验证方式”，并区分证据和推测。直接复现图案时，若所见预览与源 RGBA 不一致，先检查底色合成再选材质默认值。源文件有透明度、且底色会改变理解时，使用工具支持的显式背景合成进行对照；不能把黑色半透明图案在白底显示的灰色写成不透明灰色，也不能把所有非不透明像素一律当作完全空白。

用户明确要求改变参考中的某项特征时，按用户的新目标实现，记录有意偏离参考的部分，其余要求继续核对。

## 从当前效果提取细节标准

将决定目标效果的细节写成可比较的特征，并注明依据、目标值/范围或定性表现。按本任务选取少量有判别力的项，以下是可选维度，不是所有材质的必查清单：

- **空间与分布：**轮廓、比例、布局、纹理密度/尺度、方向、特征之间的对应或接缝连续性。以像素、归一化尺度或已知物体尺寸比较，区分特征主体和过渡范围。
- **表面响应：**粗糙/光滑感、反射或高光的范围与强度、纹理/法线细节尺度，以及相关视角或光照变化下的表现。观察到的高光不是粗糙度的直接测量值，要在可比条件下检查响应及输入。
- **覆盖与合成：**颜色、不透明度、重叠层次、过渡方向与形态。适用时沿过渡采样，区分抗锯齿、软化和光晕；共享同一边界计算不自动证明最终可见过渡一致。
- **时间与驱动：**变化方向、速率、持续时间、阶段转换、局部与整体的同步关系，以及触发/完成后的状态。根据行为类型选用时间或事件证据，静态图不能证明这些行为。

不要根据效果名称套用固定数量、形状或参数。对不确定的边界或细节给出范围或估算依据，不制造精度。数清可见部分不等于知道被遮挡的内容；屏幕形状与明暗也可能来自承载几何、投影或光照，需要结合赋予目标辨别。

保留已确认的默认值。如果场景需要更亮或更不透明的变体，应将其与匹配参考图的默认版本分开，除非用户授权更改该默认版本。

## 在有据可依的条件下比较

选择呈现同一目标特征的参考和渲染区域。记录会影响本次比较的条件：承载几何/UV、光照与反射环境、背景、相机/投影、取景尺度、曝光、色彩管理，以及时间或驱动状态。也记录使用的是材质预览还是场景视口、预览平台/渲染路径和后处理；相机相同但自动曝光仍开启，不等于颜色比较条件受控。不要拉伸图像，也不要悄悄修改材质来弥补采集条件不一致的问题。

如果现有工具和已授权的设置允许，先检查受控条件下的预览，再检查用户要求的场景材质赋予结果。不应直接认定必须创建或修改预览场景；应复用合适的现有设置，或报告当前可用视图的局限。不要假设关卡视口采集支持材质编辑器预览、任意窗口或编辑器内运行（PIE）。

使用 `unreal_visual_compare` 时，对外部美术图或尚未确认条件的视图使用评估模式（`assessment`）。只有确认相机、缩放比例、曝光及其他相关条件一致后，才使用回归模式（`regression`）；仅凭相似性不能证明已对齐。颜色分布不能证明几何形状一致，合成后的 RGB 比较也不能独立验证原图的 alpha。

按特征设定验收标准：离散关系或明确状态可以要求精确一致；尺度、偏移、响应强度、颜色或持续时间等需要适当的容差和测量依据。用户提供的标准优先。不能量化时，指出可观察差异和证据局限，不要编造通用的图像相似度阈值，也不要将参考性指标当作自动验收依据。

采集足够的证据，以解决每一项相关差异。修改参数之前，先明确差异及预期修正；在有帮助时复用现有设置和采集结果。缺少一致的比较方法时，多张截图并不能构成更有力的证据。

按偏差的影响与依赖关系排查：先确认目标资产、输出与比较条件，再检查决定本次效果的关键关系，最后细化局部差异。图形效果可能先核对布局和覆盖，受光表面则可能需要先核对纹理尺度、通道与光照响应，不能固定使用一种顺序。截图中的错误不能因为与当前节点实现一致就判为通过；源数据正确也不代表最终输出已正确使用。无法取得可比画面时，保留成立的局部结论，将未能验证的项目单独列出。

将观察到的差异写成“目标依据 → 当前结果 → 修正 → 同条件复查”，在当前授权及修复额度内主动完成修正。可辨认的细节偏差无需用户逐项重述，这也适用于参考没有专门文字标注、但对目标外观有明确贡献的特征。只有证据无法确定的核心解释或额外审美选择才需要澄清；遵守主流程的停止条件。保持用户明确要求的参考变更，不能为提高原图相似度撤销这些变更。

将外观验收与参数测试分开。临时参数检查完成后，恢复并回读本任务要求的最终值，再取得交付状态的外观证据；测试变体截图不能替代目标效果的对比。记录截图对应的资产/实例、关键参数和采集时点，避免把随后手动调整的截图当成先前交付状态。场景交付还需回读指定 Actor/组件的实际槽位，确认引用的是正式交付材质或实例；场景中已显示只证明当前赋值，材质资产及承载赋值的地图/包是否保存须分别核验。分别报告编译通过、参数行为通过及目标外观通过/有差异/未验证。

## 参数与时序检查

若只是把已有实例参数改为用户指定值，写入、回读并针对所要求的效果核验即可，不自动扫描边界值或重建控制逻辑。对于新增或改变的参数逻辑，检查默认值、一个有实际意义的非默认值，以及相关边界或禁用状态。只检查适用的约定，例如有效范围、方向或回绕方式；选择能暴露错误连接、控制范围或单位问题的用例，无需遍历所有值。

测试参数的含义和关系而不仅是“画面变了”：预期输出是否改变、关联特征是否保持约定、无关部分是否受到意外影响。适用时检查纹理缩放与细节尺度、表面属性与光照响应、覆盖与层次、驱动状态与输出的关系；只核验本任务要求的控制粒度。

区分可见性与动画开关。“是否闪烁”控制是否随时间变化，本身不意味着关闭时隐藏图形；用户没有另行约定时，保留其静态可见状态并说明这一选择，无需为此重复询问。只有文字或已有控制逻辑确实冲突时再澄清。

临时写入参数必须限于已授权的目标。记录原有值、验证结果，并恢复本任务要求的最终值，包括用户新指定的实例覆盖，不能误恢复为旧值或父级默认值。回读只能证明存储的值；渲染效果或适当的运行时观察才能证明该值影响了预期输出。

对于随时间或事件变化的行为：

1. 先区分周期变化、一次性变化或事件驱动，确认时间源/驱动输入、单位及控制器或实例覆盖。仅在有关时定义频率、相位与占空比。
2. 使用受支持的采集或运行时观察方式，记录时间戳、已知仿真时间或触发状态。周期效果通常需要多个周期；一次性/事件效果检查相关的触发、起始、演进、完成及保持/重置条件。
3. 根据要验证的变化选择采样间隔与观察点，覆盖关键过渡。周期效果应避免反复采到同一相位；快速变化或短暂状态需要足够密集的采样，少量截图可能漏掉关键行为。
4. 将实际的速率、变化方向、过渡过程和最终状态与请求比较，只检查该行为具有且用户要求的性质。

两张状态不同的图片只能证明发生变化，不能证明速率、触发、过渡或控制粒度正确。把公式推导结果与实际观察结果分开报告。

如果受支持的工具无法观察时间变化或渲染所需目标，应单独报告公式／属性检查结果，并明确说明动态验证尚未完成。如果启动或更改运行中的会话超出授权范围，不得仅为宣称更充分地完成任务而这样做。
