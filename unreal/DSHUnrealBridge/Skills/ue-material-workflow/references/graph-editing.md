# 材质图的构建与修复

修改材质图时阅读本参考文档。对于材质实例覆盖，通常只需获取当前参数值、使用受支持的更新方式，并进行有针对性的验证。

## 选择实现方式前先检查

读取当前材质域、混合/着色设置、已连接的输出、相关表达式类及属性，以及函数或参数依赖。确定可见效果来自正在编辑的资产、实例覆盖，还是运行时参数/控制器。保留无关的输出、共享函数，以及有意保留的未连接工作节点。

根据实际材质规划输入、特征生成、表面响应或覆盖、可选动态驱动与输出。只建立目标需要的功能块，不要求每种材质都有遮罩或多层合成。在适用时优先使用项目已有的函数。不要仅仅因为可以实现，就添加超出请求范围的参数化设计。

对于请求中的每个参数，明确其类型、含义、默认值、有效使用范围和单位。选择能描述其功能的名称和分组。检查参数名称冲突，以及修改函数或父材质是否会影响请求范围之外的资产。

## 将效果关系落实为图结构

在铺开节点前，列出关键计算的输入、输出和适用条件，将输出特征对应到用户要求或参考证据。检查缺失和额外的视觉贡献，避免为了接通图而引入没有依据的输出。按当前效果选用以下关系，不要求全部适用：

- 对齐、相邻或重复的部分共享相应坐标、方向、边界与间隙；一个参数变化时保持用户要求的关系。不要为本应一致的边界各自设置独立默认值后靠手调碰齐。
- 对需要一一对应的重复结构，复用单元标识与局部坐标，派生相关特征及控制。单元可以由纹理、空间划分或其他受支持的输入定义，不能预设其形状或排列；用户要求独立变化的特征保留独立控制。
- 对要求排除或透明的区域，检查覆盖函数在内部、边界和外部的实际值。衰减不自动产生排除区；需要有限宽度的空白时，应先定义真正排除的范围，再处理过渡，不能靠另一层遮住或仅在接缝点归零。
- 表面材质应将颜色、粗糙度、金属度、法线等信号送到含义匹配的输出，核对实际使用的纹理通道、色彩空间、尺度及坐标约定。贴图中的高光/阴影不等于基础色，亮度变化不等于粗糙度变化；先区分输入、光照和几何的贡献，再选择修正路径。
- 涉及透明或分层合成时，分别处理颜色与覆盖率，并按混合模式合成。预览底色上的合成 RGB 不是发光颜色；颜色参数里的 A 也不代表已连接到材质透明度输出。检查重叠区域是否因相加/饱和意外变为不透明。普通直通透明混合中，若同一衰减 `m` 同时乘进颜色和 Opacity，黑底结果会包含 `m²`，不再是单次渐变；只有目标确实要求这种衰减时才如此组合，不能将该结论套到所有模式。

用能区分正确与错误实现的少量位置、取值或状态核对关键计算：覆盖边界、纹理接缝、表面属性响应或驱动状态转换，仅选本任务相关项。编译前的计算检查用于发现建模错误，之后仍需图回读和可取得的渲染证据。

## 先验证不确定的接口

检查表达式实际的输入/输出名称、输出索引、值类型，以及通过反射暴露的可编辑属性。目录中存在某个类，并不代表已连接的工具能够写入该类的所有属性。

属性写入通常是局部更新，未指定的字段会保留节点默认值或现有值。需要单通道时明确核对所有通道开关和输出维度：例如 UE 创建的 `ComponentMask` 可能默认启用 R/G，仅设置 `R=true` 不保证输出 scalar；应按需要同时指定 `R/G/B/A`，再回读确认。遇到 `float2` 与 `float3` 等编译错误，沿报错路径检查实际通道、引脚输出和广播规则，先修正最早的类型来源，不要靠反复断连或更换资产试错。

使用 Custom（自定义）表达式时，先通过当前接口，在一个具有实际用途的最小子图上验证所需的输入声明、源代码属性、输出类型、输出引脚、下游连接和编译。确认已连接的输入按预期解析后，再添加完整实现。修改反射数组时，必须保持所保留元素的 JSON 表示完全不变。如果接口无法表达所需的输入或输出，先调查这一限制，再扩展实现或选择受支持的替代方案。

涉及角度或时间计算时，明确相应约定：

- 区分度、弧度和归一化圈数，并说明角度零点和正方向。
- 检查每个 Unreal 三角函数节点的 `Period`；不要假定其单位与 Custom/HLSL 三角函数相同。
- 显式进行单位转换，并在使用该值的输入处验证任何半角或全角关系。
- 区分每秒周期数、每秒弧度数和每周期秒数。仅按效果所需定义时间相位、范围和占空比。

例如 UE `Sine` 的 `Period=1` 时，`Time * FrequencyHz` 已表示每秒相应次数的周期，不应再无条件乘 `2π`；Custom/HLSL 的 `sin` 接受弧度，才需对应转换。以当前节点实际属性为准，转换只做一次。

编译只能验证着色器的构建，不能验证几何形状、不透明度、时序或外观是否符合预期。

## 优先采用范围受控且相互连通的批量操作

当工具声明提供的材质批量操作支持所需修改时，将节点、属性、连接和输出准备成一个完整可编译的功能批次。大型图按这类边界拆分，控制单次参数体积；不一次堆入整张图，也不为缩短请求把必要连接或输出拆到下一批。对新建节点使用该操作实际支持的引用机制。执行修改前，使用受支持的预览或预检，但不要把结构校验描述成编译成功或实际执行成功。

当前原生 `unreal_material_patch` 的 `dryRun:true` 只在临时副本中验证，不返回可供 `unreal_apply` 使用的 `previewId`，不得自行编造。通过后，使用同一 `baseRevision` 和操作，以 `dryRun:false` 及新的请求 UUID 提交；若资产已变化，则先回读并调整批次。检查返回的 `verified`、`dryRun` 和编译状态，不把预检当作实际创建。材质批次不使用蓝图的 `unreal_apply`。每批实际提交后使用其最新 revision 准备下一批；提交不等于保存，按当前返回的 `saved` 状态收尾。

检查该操作承诺的能力：支持的材质/函数类、可编辑的属性类型、支持的图操作、回滚覆盖范围、编译行为，以及是否会保存。不得假定批量工具支持材质编辑器的所有操作。如果某项必要操作不受支持，明确指出，并选择允许的实现路径，不得削弱现有保护措施。

使用需要逐项调用的接口时，每次构建一个相互连通的功能块，验证后再扩展。在连接方式尚不确定时，避免预先创建大型材质图。操作失败后，如果返回结果未确认状态已恢复，就读取受影响的状态；保留返回的节点标识，避免重试时创建重复节点。

## 展示构建过程

使用当前桥接支持的编辑器同步、打开和聚焦能力。在多批次构建中，按可编译的功能阶段展示提交后的图，并说明这一阶段实现了什么；不为逐节点演示拆散必要的连通批次。批量提交通常展示整批结果，不能承诺逐个节点出现或连线动画。

区分原始资产读回成功、编辑器图已同步、窗口已可见和节点已聚焦。只有对应返回状态或可用的界面证据才能证明后几项；不能仅因节点 ID 存在或发出了打开请求，就宣称用户已经看到过程。已打开的材质编辑器可能持有自己的未提交编辑副本；遇到编辑冲突时保留用户改动，遵循桥接返回的处理路径，不能擅自关闭重开或刷新覆盖。工具无法确认展示时如实说明，不用资产改名重建来修复窗口问题。

## 维护编辑后的材质图

在构建过程中添加说明功能的注释和有意义的参数分组。若发现可用的材质布局操作，就使用它；仅支持蓝图的自动布局能力不足以完成此任务。除非用户要求更大范围的整理，或项目已有此惯例，否则将整理范围限制在本次编辑区域。

清理前，确定实际要删除的节点集合。未连接的节点可能是有意保留的实验、共享的编辑辅助节点，也可能属于某个函数，而该函数输出的使用情况需要结合上下文判断。只删除确认已被本次任务弃用的节点，或用户明确纳入清理范围的节点。如果覆盖整个资产的未使用节点删除工具无法保留无关的未连接节点，就不要调用它。

检查最终连接、修改过的输出路径、参数默认值、编译诊断、注释和可读性。如果布局或注释操作不可用，就通过受支持的节点创建坐标保持布局清晰，并报告不受支持的部分，不得声称自动整理已成功。
